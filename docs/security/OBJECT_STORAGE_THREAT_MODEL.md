# Модель угроз объектного хранилища

Выбранный сервер development и staging — SeaweedFS 4.48. RustFS 1.0.0 в пилот не входит. Это не заключение о production-готовности.

## Доступ

- Анонимный `GET /` и запрос без верных учётных данных отвергаются.
- Production не содержит пароля в compose. Секрет читается из файла, смонтированного Docker secret.
- Порт S3 и консоль не публикуются в production и staging. Локальный порт привязан к loopback.
- `S3_ENDPOINT` задаётся конфигурацией. Клиент не принимает endpoint из тела пользовательского запроса, поэтому пользователь не выбирает произвольный адрес хранилища.
- Path-style включён. Имя bucket не превращается в hostname.
- Presigned URL продукт не выдаёт. В AuditLog не пишутся access key, secret, presigned URL, содержимое файла и полный чувствительный object key.

## Контейнер

Образ официальный, tag `4.48`, digest manifest list зафиксирован. Процесс сервера — uid 1000. Compose добавляет `no-new-privileges`. `cap_drop: ALL` не используется, потому что entrypoint образа должен кратко стартовать от root и затем сбросить привилегии. Контейнер не privileged. Healthcheck читает внутренний статус master и не создаёт объект. Служебные порты не публикуются.

Trivy 0.66.0 по `linux/amd64` digest 2026-10-01: Alpine 3.24.2 и бинарник `weed`, CRITICAL 0, HIGH 0.

## Данные

Объекты принадлежат приложению: ключ генерирует сервер, имя файла лежит в PostgreSQL. Шифрование канала до хранилища в production задаётся `https` endpoint и проверкой `S3_USE_SSL`. Шифрование диска — свойство инфраструктуры, не настройка образа. Backup приложения шифруется AES-256-GCM. Целостность проверяется SHA-256, не только ETag.

Ротация ключа: заменить файлы секретов и переменные `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY`, перезапустить `object-storage` и API. Старый ключ после ротации не остаётся в compose.
