# Модель угроз MVP

RBAC и PostgreSQL RLS — контроль доступа, не шифрование.

## Что защищено криптографически

- Пароли: Argon2id. Обратимого шифрования пароля нет.
- Идентификатор сессии: случайные не менее 256 бит, в Redis хранится только SHA-256.
- Транспорт снаружи: TLS на reverse proxy. HSTS включается только на HTTPS.
- Backup: AES-256-GCM, ключ отдельно от копий и вне Git.

## Что зависит от площадки

Шифрование PostgreSQL, MinIO и Redis at rest — свойство зашифрованного тома сервера. Приложение не подменяет его собственной криптографией. Redis persistence лежит на том же зашифрованном томе и не публикуется наружу. Ключ тома хранится в менеджере секретов площадки, не рядом с backup и не в репозитории. Ротация ключа тома — процедура площадки: новый том, копирование, переключение, уничтожение старого тома после проверки backup.

Потеря узла: поднять новый хост из manifest, восстановить PostgreSQL и MinIO из последней проверенной копии, заново ввести секреты, не извлекая их из Git.

## Что сознательно не входит в MVP

Field-level encryption не входит в MVP. Field-level AES для обычных полей актов, дефектов и справочников не требуется для первого запуска, пока действуют все четыре контроля: зашифрованный том, отдельное шифрование backup, TLS и серверный доступ RBAC/RLS. Production volumes должны быть зашифрованы инфраструктурой. CVE-2026-45447 относится к OpenSSL `PKCS7_verify()`, а не к Redis. Закрытый порт не устраняет package vulnerability. Production images immutable: сторонние образы закреплены digest, собственные — Git SHA и digest. Коммерческие поля B/C дополнительно скрыты serializer и row policy. Это не замена шифрованию тома.
