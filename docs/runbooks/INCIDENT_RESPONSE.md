# Реакция на инцидент

1. Зафиксировать время, симптом и request id. Не копировать в тикет пароли, cookie, session id, CSRF, строки подключения и вложения.
2. Проверить `/api/ready`, heartbeat worker, диск и последний успешный backup.
3. Если недоступна база, Redis, MinIO или диск выше 90%, остановить запись через maintenance page и не запускать seed/reset.
4. При подозрении на утечку сессии увеличить `sessionVersion` сменой пароля или архивацией учётной записи. Старый пароль нигде не показывается.
5. При повреждении данных восстанавливать из зашифрованного backup на отдельный инстанс и сверять manifest до переключения DNS.
6. После восстановления записать в AuditLog операционное действие через обычный API, без ручной правки секретов.
