## Часовой пояс и период

Все календарные границы — `Europe/Minsk`, фиксированный сдвиг `+03:00`. Перехода на летнее время нет, поэтому границы не зависят от DST. Фильтр `dateFrom`/`dateTo` на всех вкладках ограничивает дефекты по `createdAt`. «Закрыто за период» дополнительно требует `readyAt` в том же окне. Пустой фильтр не снимает RLS и scope.

Максимальный диапазон — 3660 дней. Drill-down: страница до 100 строк.

### Финансы

Подтверждённые затраты Dana = сумма `CONFIRMED + ACTUAL_COST + payerType=COMPANY`. Предложение `Proposal.amount` не входит. `RECOVERY` и `AVOIDED_LOSS` не смешиваются с расходом и не называются фактической экономией. `VOIDED` и `DRAFT` не входят. `ESTIMATE` и `APPROVED_AMOUNT` не входят в расход. BYN фиксируется на дату операции; для BYN курс `1`. Другая валюта требует явный курс. Корректировка подтверждённой записи — новая компенсирующая запись, не правка.

Если подтверждающих строк нет, UI показывает «Нет подтверждённых данных», не `0 BYN`.

### Качество устранения

```text
First-Time-Right =
  завершённые дефекты с ACCEPTED попыткой №1
  / завершённые дефекты хотя бы с одной попыткой
```

Рядом показывается покрытие: «N из M дефектов имеют данные о попытках». Legacy без попыток остаются в знаменателе покрытия и вне знаменателя FTR.

Rework Rate = завершённые с хотя бы одной `REJECTED` / завершённые с попытками. Average/Median Attempts считаются по дефектам с попытками. Reopened After Acceptance — есть `ACCEPTED` и более поздняя попытка.

### SLA

Для подрядного дефекта `IN_PROGRESS` идёт время подрядчика. `PENDING_INSPECTION` останавливает его и включает ожидание проверки. Отдельно: время подрядчика, ожидание проверки, календарное время. Подрядчик не обвиняется за ожидание СГР. Числового договорного SLA в модели нет, поэтому показываются длительности, а не процент «нарушил договор».

### Долг качества

Два независимых денежных показателя. Оба видны только при `VIEW_FINANCIAL_ANALYTICS` и не попадают в ответ без этой возможности.

- Подтверждённая финансовая нагрузка: `SUM(CONFIRMED, ACTUAL_COST, COMPANY) − SUM(CONFIRMED, RECOVERY)`. `ESTIMATE`, `APPROVED_AMOUNT`, `AVOIDED_LOSS`, `DRAFT` и `VOIDED` не входят. Нет таких записей — «Нет подтверждённых данных», не ноль. Отрицательный результат сохраняется.
- Риск-взвешенный открытый долг, формула `2026.10.05.2`: только открытые дефекты с денежной базой. База — последняя подтверждённая `APPROVED_AMOUNT`, иначе последняя подтверждённая `ESTIMATE`; без обеих дефект не получает вымышленную цену. Коэффициент: 1.00, просрочка +0.25, каждое отклонение проверки после первого +0.15, ожидание проверки дольше 7 дней +0.20, максимум 2.00. Сумма равна `base × coefficient`. Нулевое денежное покрытие — «Недостаточно подтверждённых финансовых данных».

Топ рисков — отдельный безразмерный балл по всей открытой выборке, затем 10 строк интерфейса. Балл: возраст (`дни/30`, максимум 3), просрочка (+2), отклонения (если есть попытки, максимум 3), нет виновной (+1), нет ответственного (+1), подтверждённая стоимость компании (`log10`, максимум 3), повторяемость типа ≥ 3 (+1). Тяжесть не подставляется. Сортировка по баллу, затем по идентификатору.

### Индекс организации

Взвешенные компоненты, веса перенормируются, если компонента нет: FTR 20, rework 15, contractor SLA 15, просрочка 15, медиана закрытия 10, повторяемость 10, подтверждённая стоимость 10, объекты с повтором 5. Организация с менее чем 5 дефектами не ранжируется. Без знаменателя объёма работ доля называется «Доля среди зарегистрированных дефектов», не «частота дефектов».

## Паттерны

Движок детерминированный, версия правил `2026.10.05.2`. Не больше трёх измерений в заранее заданных срезах, не полный перебор. Сравнение с baseline той же видимой выборки. Доля оценивается интервалом Уилсона с `z = 2.9`. Минимумы: support 5, объекты 2, coverage 0.6. Малая выборка не получает сильную формулировку. «Подтверждённая закономерность» появляется только после ручного статуса `CONFIRMED`. Текст говорит «наблюдается», «связано», «выше базового уровня» и не говорит «является причиной».

`LOW_FIRST_TIME_RIGHT` — отдельное правило. Сигнал выпускается, если в сегменте не меньше 5 завершённых дефектов с попытками, coverage не ниже 0.60 и First-Time-Right ниже baseline не меньше чем на 0.15. Пустое измерение сегментом не считается.

Каждый выпущенный сигнал хранит неизменяемый support: дефекты, которые вошли в расчёт, причину включения, версию правила, момент расчёта и hash канонического фильтра. Новый расчёт с другим support создаёт новый снимок. Старый сигнал без support показывает «Support snapshot unavailable» и не дополняется предположительно. Drill-down сигнала не расширяется общими фильтрами и пересекается с текущим доступом пользователя.

Типы: `COST_CONCENTRATION`, `SLOW_RESOLUTION`, `HIGH_REWORK`, `LOW_FIRST_TIME_RIGHT`, `OVERDUE_CONCENTRATION`, `REPEATED_DEFECT_ACROSS_OBJECTS`, `RESPONSIBILITY_CONCENTRATION`, `INSPECTION_BOTTLENECK`, `DATA_QUALITY_RISK`.

## Попытки и доказательства

Переход `IN_PROGRESS → PENDING_INSPECTION` создаёт попытку. Принятие и возврат закрывают текущую `PENDING` попытку. Повторная передача создаёт следующий номер. Номер уникален, `PENDING` одна, принятые и отклонённые неизменяемы, удаление запрещено. Старые дефекты без попыток не заполняются. `REPAIR_EVIDENCE` связывается только если файл `READY`; после связи он неизменяем и не переносится на следующую попытку. Непроверенный файл доказательством не становится.

## Ограничения интерпретации

Корреляция в срезе не является причиной. Нет знаменателя объёма работ. Нет тяжести, секции, этажа, материала. Нет отдельной метки назначения инженера. Предложение не является расходом. Подтверждение сигнала человеком не превращает наблюдение в причинное исследование.
