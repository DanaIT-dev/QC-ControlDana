# Контракт объектного хранилища

Контракт описывает операции, которые QC выполняет с S3-совместимым хранилищем. Операции, которых продукт не вызывает, не входят в обязательный набор.

Провайдер выбран после одного и того же harness на disposable-окружениях. Development volume в этих прогонах не использовался.

## MUST

- Endpoint отвечает, а учётные данные проходят `HeadBucket`.
- Bucket создаётся идемпотентным bootstrap (`HeadBucket`, затем `CreateBucket`, если bucket отсутствует). Обычная readiness вызывает только `HeadBucket` и не записывает объект.
- Анонимный доступ, неверный access key и неверный secret key отвергаются.
- `PutObject` для небольшого объекта.
- `HeadObject` возвращает `Content-Length`.
- `GetObject` возвращает те же байты. Сравнение — SHA-256.
- `Content-Type` сохраняется и читается.
- `DeleteObject` удаляет объект. Повторный `DeleteObject` не публикует объект заново.
- `GetObject` отсутствующего ключа завершается безопасной ошибкой, без падения API.
- Внутренний ключ — `attachments/<uuid>` либо, в тесте, `runs/run-<uuid>/attachments/<uuid>`. Исходное имя файла не становится ключом.
- Символы управления в отображаемом имени отбрасываются до записи в PostgreSQL. `..` и двойное расширение отвергаются. Path traversal не записывается как object key.
- Загрузка больше порога multipart идёт через `@aws-sdk/lib-storage` `Upload`. Порог по умолчанию — 5 MiB (`S3_MULTIPART_THRESHOLD_BYTES`).
- Незавершённый multipart прерывается через `Upload.abort`. После abort объект не читается.
- `GetObject` с заголовком `Range` возвращает запрошенный диапазон. Скачивание стримится и не собирает объект целиком в память API.
- Антивирусный контур приложения: worker читает поток и передаёт его в ClamAV `INSTREAM`. Чистый файл получает статус `READY`, объект остаётся. EICAR получает `REJECTED`, `objectKey` очищается, объект удаляется. Недоступный ClamAV после исчерпания попыток даёт `SCAN_FAILED`: объект остаётся, скачивание запрещено, потому что `canDownloadAttachment` истинен только для `READY`.
- Ошибка загрузки удаляет записанный объект и строку вложения. Повторная загрузка того же содержимого удаляет новый объект.
- Максимальный размер вложения — 20 MiB.
- Клиент S3 использует timeout и до трёх попыток SDK. Отмена запроса использует `AbortSignal`.
- После перезапуска контейнера загруженный объект читается с тем же SHA-256.
- Backup/restore disposable-окружения восстанавливает каждый объект, размер, SHA-256 и не добавляет лишних объектов.
- Официальный образ имеет неизменяемый tag и подтверждённый `linux/amd64` digest. Анонимный доступ к bucket запрещён.

## SHOULD

- Metadata ASCII, которую кладёт сам клиент, читается обратно. QC не пишет исходное имя файла в S3 metadata: имя хранится в PostgreSQL (`originalFilename`, `safeDisplayName`).
- Кириллица допустима в отображаемом имени после нормализации и не участвует в object key.
- Пробелы, кавычки и длинное исходное имя остаются данными отображения, а не ключом.
- `Content-Length` ответа совпадает с размером объекта.
- ETag присутствует. QC не использует ETag как единственную проверку целостности; проверка содержимого — SHA-256 на стороне приложения.
- Healthcheck контейнера — `GET /health` без записи объекта.

## NOT_REQUIRED

- Presigned `PUT` и presigned `GET`. Продукт их не создаёт. `S3_PRESIGNED_TTL_SECONDS` принимается конфигурацией и не используется для подписи URL.
- `CopyObject` и отдельный quarantine bucket. Карантин — это статус строки и удаление объекта, а не копирование между bucket.
- Переименование объекта.
- Версионирование bucket, object lock, lifecycle rules.
- Виртуальный host-style. Клиент работает с `forcePathStyle: true`.
- Публичный анонимный download.
- Запись тестового объекта из readiness.

## Harness

`apps/api/scripts/object-storage-contract.mjs` принимает endpoint, region, bucket и учётные данные через окружение и не содержит имени провайдера. Он отказывается работать с `sgr-attachments`, `sgr-attachments-test` и `sgr-attachments-e2e`.
